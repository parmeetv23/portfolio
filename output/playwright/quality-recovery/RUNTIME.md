# Runtime diagnosis

- The prior :3002 server used a snapshot in `/tmp/portfolio-final-check`, so workspace edits were not live.
- Workspace startup was blocked before binding a port. Process sampling showed synchronous `pread`; lsof identified `node_modules/next/dist/compiled/lru-cache/package.json`, marked `compressed,dataless`. The file read itself stalled. No component code had run.
- Restored 1,219 evicted files from the installation with the identical package-lock SHA-256 (`e1f0b87aa264ca41227aca57404aecaf7f1662f879a4650138aae57283f9d8bc`). More installed files were subsequently evicted while lint/build ran, including es-errors and styled-jsx. Simply restarting was insufficient.
- Moved the unstable installation to ignored `.node_modules-cloud-backup/`; `node_modules` now links to the healthy `/tmp/portfolio-final-check/node_modules`. The source and server remain in the real workspace. Manifest, lockfile and dependency versions are unchanged.
- The first browser audit after switching that dependency path found duplicate React identities in dev chunks: old `./node_modules/next/.../react` plus the resolved `/private/tmp/.../react` path. This was introduced by changing dependency identity under a running compiler. The console showed invalid hook calls and `useContext` null, distinct from the originally reported undefined `call`. Stopped that process, removed only generated `.next-dev`, and restarted with the consistent path. A fresh browser session is used for the final audit.
- The old config defaulted dev and build to `.next`. Config now chooses `.next-dev` for development and `.next` for production by phase. This prevents production validation from replacing live dev chunks/manifests. The Next.js 14 configuration supports phase-dependent `distDir`: https://nextjs.org/docs/14/app/api-reference/next-config-js .
- The exact historical `undefined.call` exception was not captured or reproduced. Stale/mixed module output is consistent with that stack, but its historical trigger cannot be proven from the supplied trace alone. Final cold/direct/client-transition and concurrent-build results are recorded separately; no errors are suppressed in the application.
